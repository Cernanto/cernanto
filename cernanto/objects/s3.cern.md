# cernanto/objects/s3

Type: module

Implements: cernanto/objects
Uses: cernanto/config, npm:@aws-sdk/client-s3@3.1159.0, npm:@aws-sdk/lib-storage@3.1159.0

The objects of a plane that runs on AWS, kept in one S3 bucket, the
plane's own, the bucket the runtime keeps its own objects in (its
spilled record texts among them), every object under the key
`objects/<name>`, the name verbatim. It answers the objects
interface's seven operations over the bucket; a call made where no
place is named, and a name whose segment is empty, `.` or `..`, are
refused in words.

## The place and the identity

THE PLACE is the block's word `machine.substrate` in this copy's
working folder's `materialized.json`, read with the file system's own
read once and kept for the life of the process, when it is a
`dynamodb:` url,
`dynamodb://<region>/<table>?bucket=<bucket>`, whose `bucket` and
region this module uses; when the mark names another kind of place
(a laptop's `file:` url), the configuration's setting
`place` names it, read through cernanto/config. A process
with neither refuses every call with exactly `no S3 place is named`.
THE IDENTITY is the SDK's default chain: the instance role through
the metadata service on a server, the operator's own sign-in on a
laptop.

## The operations

Every put writes the object's metadata `sha256`, the hex digest of
its bytes. PUT writes the bytes as one object, a reader seeing the
whole object or none; a target whose bytes are the given ones already
(the same length and the same sha256, read from the metadata) is
answered as done, the object left as it is. GET answers the object's
bytes whole, null when there is none. PUT FILE makes the file at the
path given the object under the name, a file of hundreds of megabytes
included, the metadata computed over the file as it goes up, a reader
seeing the whole object or none, and the file gone from its path once
the object is whole; a target already there is replaced. GET FILE
writes the object to the path given, the file appearing whole,
answered as done, or null when there is no object. REMOVE deletes the
object, a name with no object answering the same. LIST answers every
name under the prefix, the keys under `objects/<prefix>`, the prefix
matched on the whole name. DESCRIBE answers the object's size and its
last-modified moment, or null.

## Tests

The tests run live against the bucket the place names, under names
of their own under a prefix named by a random token, and remove every
object they put at the end, every other object left as it is. They
prove the round trip of bytes of a few megabytes, the same-bytes put
answered with the object left as it is, the put of a file and the get
into a file (the file gone from its path after the put, the bytes
whole after the get), the listing of a prefix, the description's
size, the removal of a name twice, and a name of plain text: names
whose segments carry a `:`, a `#`, a space and an `=`, letters beyond
Latin and a character beyond the Basic Multilingual Plane each hold
their own bytes, and are listed under their prefix exactly as they
were handed.
